# Config File Generation Validation and Testing

## Original Objective

Accurately check and test the config file generation system to ensure:
1. All sections written to new config files (both global and local) are correct and handled by keecas
2. Changes in local config files are actually respected by keecas (sample testing, not exhaustive)

## Problem Statement

The config system has grown complex with:
- Template generation in `manager.py:_generate_config_template()` (894-1055)
- Multiple sections: latex, display, language, translations, check_templates
- Hierarchical inheritance (local > global > defaults)
- Environment definitions (7 built-in: align, equation, gather, cases, rcases, split, alignat)
- Custom environment extensibility
- Version metadata headers
- Migration system (0.1.0 → 1.0.0)

**Current gap**: No systematic validation that generated config files:
1. Parse correctly as valid TOML
2. Contain all advertised sections/keys
3. Actually affect keecas behavior when modified
4. Match documentation and code expectations

## Analysis of Current Implementation

### Config Template Generation (`manager.py:894-1055`)

**Version Header** (919-926):
```python
# Generated by keecas v{__version__}
# Schema version: {schema_version}
# Created: {now}
# Last updated: {now}
```

**Sections Generated**:
1. **[latex]** (976-989):
   - `eq_prefix`, `eq_suffix`, `vertical_skip`
   - `default_environment`, `default_label_command`, `default_mul_symbol`
   - Comments about `label` (runtime-only callable, not serializable)
   - Environment customization examples

2. **[latex.environments]** (990-1005):
   - Built-in: align, equation, gather, cases, rcases, split, alignat
   - Custom environment example with all fields
   - Shows `EnvironmentDefinition` structure

3. **[display]** (1007-1018):
   - `print_label`, `debug`, `katex`
   - `default_float_format` (None default with example)
   - `pint_default_format`

4. **[language]** (1020-1024):
   - `language` (optional, commented in template)
   - `disable_pint_locale` (default True)
   - Comments explaining behavior

5. **[translations]** (1026-1028):
   - Empty section with inheritance note for local configs

6. **[check_templates]** (1030-1046):
   - `success_template`, `failure_template` (literal strings)
   - Three named template sets: default, boxed, minimal
   - Each set has success/failure templates

**Local vs Global Differences**:
- Global: All values active (uncommented)
- Local: Values commented with `#` prefix for easy toggle
- Local shows inherited global values in comments

## Risks and Mitigations

**Risk 1**: Tests may reveal bugs in config system
- **Mitigation**: Allocate time for fixes in Phase 5
- **Benefit**: Better robustness before 1.0.0 release

**Risk 2**: Some config options may not propagate correctly
- **Mitigation**: Focus on high-priority user-visible settings first
- **Benefit**: Identifies critical bugs early

**Risk 3**: Template generation may not match loading logic
- **Mitigation**: Test round-trip (generate → load → verify)
- **Benefit**: Ensures consistency
