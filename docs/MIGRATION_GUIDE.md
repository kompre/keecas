# Configuration Migration Guide

## Overview

Keecas uses an automatic configuration migration system to handle breaking changes between versions. When you upgrade to a new version, your configuration files are automatically migrated while preserving all your customizations.

## How Migration Works

### Automatic Migration

Migration happens automatically when you:
1. Import keecas (`from keecas import ...`)
2. Run any keecas CLI command
3. Load a config file with an older schema version

**What happens:**
1. Keecas detects your config version from the header
2. Creates a backup (`config.toml.backup`)
3. Migrates your settings to the new format
4. Saves the updated config with new version metadata
5. Reports what was changed

### Manual Migration

You can also trigger migration manually:

```bash
# Check version status
keecas config version --global
keecas config version --local

# Migrate manually (creates backup)
keecas config migrate --global
keecas config migrate --local

# Dry run (preview changes without modifying)
keecas config migrate --dry-run
```

## Version History

### Version 1.0.0

**Breaking Changes:**

1. **`pint_default_format` relocated**
   - **Old**: `pint_default_format = ".3f~P"` (top level)
   - **New**: `display.pint_default_format = ".3f~P"` (in display section)
   - **Migration**: Automatic - value preserved and moved

2. **`float_precision` removed**
   - **Old**: `float_precision = 3` (numeric precision)
   - **New**: `display.default_float_format = ".3f"` (format string)
   - **Migration**: Automatic - converted to format string

3. **`sep` deprecated**
   - **Old**: `sep = "&"` (global separator)
   - **New**: `config.latex.environments.align.separator = "&"` (environment-specific)
   - **Migration**: Manual - too complex for auto-migration
   - **Timeline**: Deprecated in v1.0.0, removed in v2.0.0

**Config File Format Changes:**

Version metadata now included in header comments:
```toml
# Generated by keecas v1.0.0
# Schema version: 1.0.0
# Created: 2025-10-03T12:34:56
# Last updated: 2025-10-03T14:22:10

# Your configuration below
language = "en"
...
```

### Version 0.1.0

Base version - no migration needed.

## Migration Examples

### Example 1: Automatic Migration from 0.1.0 to 1.0.0

**Old config (0.1.0):**
```toml
language = "it"
katex = true
pint_default_format = ".4f~P"
float_precision = 4
```

**After automatic migration (1.0.0):**
```toml
# Generated by keecas v1.0.0
# Schema version: 1.0.0
# Created: 2025-01-15T10:00:00
# Last updated: 2025-10-03T15:30:00

language = "it"
katex = true

[display]
pint_default_format = ".4f~P"
default_float_format = ".4f"
```

**Migration output:**
```
WARNING: Config migration required: 0.1.0 -> 1.0.0
Backup created: /path/to/config.toml.backup
Migrated 'pint_default_format' -> 'display.pint_default_format' (value: .4f~P)
Converted 'float_precision=4' -> 'display.default_float_format=".4f"'
SUCCESS: Config migrated successfully to 1.0.0
```

### Example 2: Custom Settings Preserved

**Old config with custom settings:**
```toml
language = "de"
my_custom_key = "my_value"
pint_default_format = ".2f~P"
```

**After migration:**
```toml
# Generated by keecas v1.0.0
# Schema version: 1.0.0
# Created: 2025-02-01T08:00:00
# Last updated: 2025-10-03T16:00:00

language = "de"
my_custom_key = "my_value"  # ← Custom setting preserved

[display]
pint_default_format = ".2f~P"
```

Custom keys that aren't in the schema are always preserved.

### Example 3: Handling Deprecated Keys

**Config with deprecated `sep`:**
```toml
sep = "|"
language = "fr"
```

**After migration:**
```toml
# Generated by keecas v1.0.0
# Schema version: 1.0.0
# Created: 2025-03-10T14:30:00
# Last updated: 2025-10-03T17:00:00

sep = "|"  # ← Still present (deprecated, removed in v2.0.0)
language = "fr"
```

**Warning displayed:**
```
DeprecationWarning: `sep` is deprecated. Use `config.latex.environments.align.separator` instead.
This key will be removed in keecas v2.0.0
```

**Manual update needed:**
```python
# In your notebook/script
from keecas import config

config.latex.environments.align.separator = "|"
```

## Troubleshooting

### Migration Failed

If migration fails:

1. **Check the backup:** `config.toml.backup` contains your original settings
2. **Restore manually:** `cp config.toml.backup config.toml`
3. **Report the issue:** Include error message and config file (redact sensitive data)

### Config Reverted After Migration

If your config appears to revert:

- **Cause:** Multiple config files (global + local)
- **Solution:** Check both locations:
  ```bash
  keecas config path --global
  keecas config path --local
  ```
- Migrate both files if needed

### Custom Keys Disappeared

Custom keys should never disappear. If they do:

1. Check backup file: `cat config.toml.backup`
2. File a bug report with before/after config

### Version Number Doesn't Update

If schema version stays at old value:

- **Cause:** Insufficient permissions to write file
- **Solution:** Check file permissions, run with appropriate privileges

## Best Practices

### Before Upgrading

1. **Review changelog:** Check for breaking changes
2. **Backup manually:** `cp ~/.keecas/config.toml ~/.keecas/config.toml.pre-upgrade`
3. **Test in local config:** Upgrade local project config before global

### After Upgrading

1. **Verify migration:** `keecas config version`
2. **Check settings:** `keecas config show`
3. **Test functionality:** Run your notebooks/scripts
4. **Update deprecated usage:** Address deprecation warnings

### Version Control

**Track your config in git:**
```bash
# Local project config
git add .keecas/config.toml
git commit -m "chore: Migrated config to v1.0.0"
```

**Don't track sensitive data:**
```gitignore
# .gitignore
.keecas/config.toml  # If contains API keys, tokens, etc.
```

## FAQ

**Q: Will migration delete my custom settings?**
A: No. All user-customized values are preserved. The migration only transforms structure and converts deprecated formats.

**Q: Can I roll back a migration?**
A: Yes. Use the automatic backup: `cp config.toml.backup config.toml`

**Q: What if I skip a version?**
A: Migration handles intermediate versions automatically. Going from 0.1.0 → 1.5.0 applies all intermediate migrations in order.

**Q: How do I disable automatic migration?**
A: Automatic migration cannot be disabled. It ensures config compatibility with the current keecas version.

**Q: Will my config work with older keecas versions?**
A: No. Once migrated to v1.0.0, the config won't work with v0.x. Keep the backup if you need to downgrade.

**Q: Can I manually edit the migrated config?**
A: Yes. The migrated config is a standard TOML file. Just preserve the header comments for version tracking.

## Migration Principles

The migration system follows these principles:

1. **User Data Preservation:** Never lose user-customized values
2. **Automatic Conversion:** Convert formats when possible
3. **Clear Communication:** Report all changes made
4. **Safety First:** Always create backups before modifying
5. **Graceful Deprecation:** Warn early, remove later
6. **Transparent Process:** Users can preview and verify changes
